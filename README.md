# CURLING PARTY

上から見下ろしの 2D カーリング（縦画面：手前から奥へ投げる）。全チームが**同時に**投げる、パーティ寄りのルール。
Firebase Realtime Database でオンライン対戦。設定なしでもオフライン（CPU 対戦）で遊べる。

## 起動

ES Modules を使うのでローカルサーバ経由で開く（`file://` では動かない）。

```bash
npm start            # = npx http-server . -c-1 -p 8080 -o
```

## オンライン対戦の準備（Firebase）

1. [Firebase コンソール](https://console.firebase.google.com/) でプロジェクトを作る
2. **Realtime Database** を作成（ロケーションはどこでも可）
3. プロジェクトの設定 → マイアプリ → ウェブアプリを追加し、表示された設定値を `src/firebase-config.js` に貼る（`databaseURL` 必須）
4. Realtime Database の「ルール」に `database.rules.json` の内容を貼って公開

> ルールは `rooms/` 以下を誰でも読み書きできる最小構成。公開する場合は Firebase Authentication（匿名認証）を足してルールを絞ること。
> 終わったルームのデータは自動削除されないので、たまにコンソールから `rooms` を消す。

ルームを作ると 4 文字のコードと招待リンク（`?room=XXXX`）ができる。同じ PC で試すなら別タブで開けば別プレイヤーになる。

## ルール

- 1エンドで各プレイヤーが石を **4つ**（設定可）投げる。全員が**同時に・好きなタイミングで**投げられる
- **期限**：k 投目は「開始 + ずれ + k × 期限」までに投げる（期限はロビーで 5〜120 秒から選ぶ。標準 30 秒）。過ぎると石が 1 つ消える（間に合ったかは投げた時刻で判定するので、通信が遅れて届いても期限内に投げていれば有効）
- 得点計算は、全員が投げ終わり石が全部止まってから 1 秒後
- **ずれ**：チームごとにタイマーの開始がずれる（自動 = 期限 ÷ チーム数。標準の 30 秒・2チームなら 15 秒）。ハンマーのチームが一番遅い
- **ハンマー（最後の一投）**：エンドごとに決まったチームの 1 人だけが持つ。他の全員が投げ終わり、石が全部止まってから解禁され、そこから期限の秒数以内に投げる
  - ハンマーのチームが得点したら次のチームへ移る。0 点（ブランク / スチールされた）なら同じチームが持ち続ける
- **得点**：ティーに一番近い石のチームが、他チームの一番近い石より内側にある自分の石の数だけ得点
- 遠いほうのホッグラインを越えずに止まった石（何にも当たっていないもの）、サイドに触れた石、バックラインを完全に越えた石は除外
- モード：**1チーム1人**（基本）／**チーム戦**（2〜8チーム）。同じチームでも別プレイヤーなら同時に投げられる（石の色は同じ）
- CPU をロビーで追加できる（ホストのブラウザで動く）
- **石の速さ**：`src/config.js` の `SPEED.k` で決める（0.5 = ゆっくり、2 = 速い）。速さを変えても止まる位置・曲がり方・強さ（%）の意味は同じで、かかる時間だけが変わる（摩擦とカールは速さの2乗に合わせて自動調整）

## 操作

| 操作 | 入力 |
|---|---|
| 位置（左右） | マウス左右（A / D・←→ で 1 単位ずつ微調整、Shift で 5） |
| 投げる | 押して**下へ引き**、離す。引く長さ＝強さ、引く向き＝狙い（最大 ±17°） |
| 精密モード | ドラッグ中に Shift（感度 1/4） |
| 回転 | ホイール / Q・E（Shift で細かく）、R でリセット。強いほど大きく曲がり、遅くなるほどよく曲がる |
| スイープ | Space 長押し：自分の最新の石が滑りやすく（伸びる）・曲がりにくくなる |
| キャンセル | 右クリック / Esc |
| 自分の軌跡 | T で表示／非表示 |

ドラッグは画面のどこから始めてもよい。押した場所に「引いた量」と「投げる向き・強さ」の矢印が出る。

狙い線は**向き＋強さのゲージ**（10%刻みの目盛り、先端に%表示、20% と 90% の目盛りは長め）。線はまっすぐな向きしか示さないので、カールは自分で読む。

**強さ**（まっすぐ・スイープなしのとき）

| 強さ | 止まる位置 |
|---|---|
| 0% | 奥のホッグラインに少し届かない |
| 20% | ハウスの手前のふちにギリギリ届く |
| 約53% | ティー（中心） |
| 90% | バックラインを越える |
| 90〜100% | テイクアウト用。初速が一気に最大まで上がる |

20〜90% の間は止まる距離が強さに比例する。回転をかけると弧を描くぶん少し手前に止まり、スイープすると伸びる。

## 画面

- エンドごとの点数表を常に表示（横長画面は左パネル、縦長画面は上部）。進行中のエンドの列は薄く塗られ、各エンドでハンマーを持っていたチームに小さな黒丸が付く

## 自分の軌跡と予測線

- **軌跡**：自分が投げた石の通り道が点線で残る（自分の画面だけ、エンドごとにリセット）。スイープした区間はうすい帯、止まった位置は点線の円（場外なら ×）。投げ始めた位置に強さ（%）が出る。T で表示／非表示
- **予測線**：自分の石が動いている間、「今スイープをやめたらどこを通ってどこに止まるか」を線と石の輪郭で表示する。スイープすると予測が伸びるので、ハウスに届くか見ながら掃くかどうか決められる（他の石との衝突は考えない。何かに当たった石には出さない）

- **ハンマーの最後の一投の予測（冴えわたり）**：ハンマーの人が最後の一投を狙っている間（ドラッグ中）は、**全員の画面に**、今の狙いで投げたときの結果を他の石との衝突も含めて計算して表示する。自分の石の通り道は最後まで伸びる実線、弾かれる石の通り道は点線、全部止まったときの位置は石の輪郭（場外は ×）。計算は本物と同じ物理なので、スイープしなければその通りになる。ハンマーの人がどこを狙って迷っているかが全員に見え、その間「冴えわたり」の説明が画面に出続ける。CPU がハンマーのときも、投げる前に約2秒狙って考える様子が見える

## 演出

技の演出はシートの少し横に出て、どの石の演出か線で結ばれる（石が動いていれば線も追従）。

- **テイクアウト！ / ダブルテイクアウト！！ / トリプル… / クアドラプル…**：1 投の連鎖で他チームの石を場外に出した数（連鎖中にカウントアップ）
- **ガードストーン！**：ハウスの外・手前に止まった石が、ハウス内の自チームの石への進路をふさいだとき。ガードの石には「ガード」の札が付き、ガードの石と守られている石を結ぶ点線、ガードの手前側の円弧、守られている石の円とあわせて、ガードが成り立っている間ずっと表示される（どちらかが弾き出されるか、位置がずれてガードでなくなると消える）
- **ボタン！**：ボタンに止まったとき
- **ハンマータイム**：最後の一投が解禁されたとき。「冴えわたり（狙っている間、投げた結果が予測で見える）」の説明つき
- **スティール！！**：ハンマーを持っていないチームがそのエンドで得点したとき（小さく意味の説明つき）
- **ビッグエンド！！！**：1エンドで3点以上取ったとき（`RULES.BIG_END` で変更可）。ハウス全体が何度も弾ける
- 投げた瞬間に「ポーン」と響くサイン波の音。他の人が投げた音も聞こえ、人ごとに音の高さが違う（ドレミソラの音階から選ぶので重なってもきれいに響く）

## 仕組み

- **ホスト権威型**：ルームのホスト（最初に作った人。抜けたら次に古い参加者が自動で引き継ぐ）が物理・タイマー・得点・技判定・CPU を担当し、石の状態を約 10Hz で `stones` に書く
- **クライアント予測**：各クライアントも同じ物理を回し、自分の投球は即座に表示。ホストのスナップショット到着時に遅延分だけ先に進めて補正し、ずれは描画オフセットでなめらかに吸収
- 時刻は Firebase のサーバ時刻オフセットで揃える（期限の判定がずれないように）

```
index.html / style.css
src/
  config.js          シート寸法・物理定数・色
  physics.js         石の物理（摩擦・カール・スイープ・衝突・場外判定）
  rules.js           期限・投球可否・得点計算（ホスト/クライアント共通）
  host.js            ホスト側ロジック（エンド進行・技判定・CPU・スナップショット）
  bot.js             CPU のショット計画（単体シミュレーションで逆算）
  client.js          入力・予測・補正・演出
  render.js          Canvas 描画（線だけの人物、HUD、バナー）
  sfx.js             WebAudio 合成の効果音
  store.js           Firebase / ローカル（メモリ）の同期レイヤー
  firebase-config.js Firebase 設定（要編集）
  main.js            画面遷移・ルーム・ホスト選出
```

フィールドの大きさは `src/config.js` の `FIELD` で決める（シート幅、ハウス・ストーンの半径、ハウスの円の比率、ハック〜ホッグ〜ハウスの各区間の長さ）。各ラインの座標 `SHEET` と強さ→距離の対応はそこから自動で計算される。

調整したい値は `src/config.js`（摩擦 `MU`、カール `CURL_K`、スイープ効果、反発係数、最高速度、強さ→距離の対応 `powerToSpeed` など）。

注意：ホストのタブがバックグラウンドになるとブラウザがタイマーを間引くため、ホストは画面を前面にしておくのがおすすめ。
